# Esmbler.Kernel.Infrastructure

Adapters and application services for the kernel: PostgreSQL (EF Core + Npgsql), SQL migrations, RLS unit of work, OpenFGA, record/config/draft/publish/upgrade/preview services, activation health check, workflow definition versions (`Configuration/WorkflowVersions.cs`), outbox dispatcher (per-consumer transactions, `kernel.consumer_failures`, retention through `kernel.purge_outbox`), `Events/EventWriter.cs` (every outbox write: envelope v2, legacy reads), job runner and job handlers (`upgrade.run`, `workflow.migrate`, `approval.expire`, `sla.check`), event consumers (record projection, notifications, fulfillment, approvals), and the approval engine (`Approvals/ApprovalService.cs`, `Approvals/ApprovalConsumer.cs`, ADR 0016).

- Data access only through `Persistence/Database` (`InTenantAsync`, `InTenantWideAsync`, `AsPrincipalAsync`, `AnonymousAsync`), which sets `app.tenant_id`/`app.environment_id`/`app.principal_id` transaction-locally.
- Migrations: `Migrations/NNNN_*.sql`, applied by `MigrationRunner` as `esmbler_migrator`; never edit applied files.
- Authorization store: one OpenFGA store per tenant, model `Authorization/platform-model.fga(.json)`; derived from `kernel.group_members`/`kernel.role_assignments`. `AccessService` caches facts per (tenant, principal, `authz_revision`) for 5 s; sensitive actions (publish, rollback, modules, permission admin) and job re-authorization pass `fresh: true`.
- Activation (`ConfigActivator`) runs `ActivationHealthCheck` inside the activation transaction; a failure rolls the revision back. It also registers workflow definition versions (`kernel.workflow_definitions`) and schedules `workflow.migrate` when a changed workflow's policy is migrate or cancel.
- Approvals: every decision, expiry or cancellation first locks the request row; decisions refuse agent contexts, the requester (also through delegates) and a second decision by one person in a stage; approvals run on their policy snapshot; the request moves only through the binding's system transitions (`RecordService.SystemWriteAsync`); approvers get read access through the request's `principals` approvers field, which only the platform writes. `kernel.approval*` rows are never deleted.
- SLAs (ADR 0018): `Sla/SlaService.ApplyAsync` runs inside every record write transaction (after the record row is written, while it is locked) and `CancelAsync` on delete; `kernel.sla_timers` rows are never deleted and keep their snapshot; the `sla.check` job completes itself before scheduling the next check (the scheduler cannot move a running job).
- Metrics (ADR 0019): `Records/QueryCompiler.Where` is the one WHERE clause for lists, explorer group counts and metrics (permission predicate inside SQL, SLA breach conditions, search); never build a separate query path for figures, or figures and the explorer stop agreeing. `Metrics/MetricService` evaluates figures in the tenant transaction, each in a savepoint under a 5 s statement timeout within an overall request budget (`MetricService.RequestBudget`, 8 s; figures not reached report `timeout`), returns a `DrillQuery` per figure, bar and row (date windows as absolute instants), and computes nothing for restricted metrics (roles, hidden fields, no `records:read`; dashboard data leaves them out). `QueryCompiler.MaxCount` caps explorer totals and figures alike. `ExperienceService` removes restricted tiles and metric saved views, prunes data-table `groupBy`/`groupOptions` on fields hidden from the viewer, and lists visible dashboards in the bootstrap.
- Draft change sets (REQ-WS-005): `DraftService.ApplyBatchAsync` validates and records several ops as one change (`kernel.draft_commands.batch_id`, migration 0011): all or none, one version, undone and redone together. `ApplyAsync` is a batch of one. `SetUndoneAsync` requires `permissions.admin` to undo or redo a step or batch containing a permission-affecting op, as applying it does.
- Events (ADR 0017): publish only through `EventWriter` in the caller's transaction; each consumer runs in its own tenant transaction and must be idempotent (inbox); a consumer that keeps failing dead-letters alone (queue `consumers` in `OperationsService`).
- Invariants: record change + audit + outbox in one transaction; queries filter by permission inside SQL; no secrets in audit details.
- Tests: `dotnet test tests/Esmbler.IntegrationTests` (needs Docker).
