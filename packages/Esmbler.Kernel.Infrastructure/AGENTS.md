# Esmbler.Kernel.Infrastructure

Adapters and application services for the kernel: PostgreSQL (EF Core + Npgsql), SQL migrations, RLS unit of work, OpenFGA, record/config/draft/publish/upgrade/preview services, activation health check, workflow definition versions (`Configuration/WorkflowVersions.cs`), outbox dispatcher (per-consumer transactions, `kernel.consumer_failures`, retention through `kernel.purge_outbox`), `Events/EventWriter.cs` (every outbox write: envelope v2, legacy reads), job runner and job handlers (`upgrade.run`, `workflow.migrate`, `approval.expire`), event consumers (record projection, notifications, fulfillment, approvals), and the approval engine (`Approvals/ApprovalService.cs`, `Approvals/ApprovalConsumer.cs`, ADR 0016).

- Data access only through `Persistence/Database` (`InTenantAsync`, `InTenantWideAsync`, `AsPrincipalAsync`, `AnonymousAsync`), which sets `app.tenant_id`/`app.environment_id`/`app.principal_id` transaction-locally.
- Migrations: `Migrations/NNNN_*.sql`, applied by `MigrationRunner` as `esmbler_migrator`; never edit applied files.
- Authorization store: one OpenFGA store per tenant, model `Authorization/platform-model.fga(.json)`; derived from `kernel.group_members`/`kernel.role_assignments`. `AccessService` caches facts per (tenant, principal, `authz_revision`) for 5 s; sensitive actions (publish, rollback, modules, permission admin) and job re-authorization pass `fresh: true`.
- Activation (`ConfigActivator`) runs `ActivationHealthCheck` inside the activation transaction; a failure rolls the revision back. It also registers workflow definition versions (`kernel.workflow_definitions`) and schedules `workflow.migrate` when a changed workflow's policy is migrate or cancel.
- Approvals: every decision, expiry or cancellation first locks the request row; decisions refuse agent contexts, the requester (also through delegates) and a second decision by one person in a stage; approvals run on their policy snapshot; the request moves only through the binding's system transitions (`RecordService.SystemWriteAsync`); approvers get read access through the request's `principals` approvers field, which only the platform writes. `kernel.approval*` rows are never deleted.
- Events (ADR 0017): publish only through `EventWriter` in the caller's transaction; each consumer runs in its own tenant transaction and must be idempotent (inbox); a consumer that keeps failing dead-letters alone (queue `consumers` in `OperationsService`).
- Invariants: record change + audit + outbox in one transaction; queries filter by permission inside SQL; no secrets in audit details.
- Tests: `dotnet test tests/Esmbler.IntegrationTests` (needs Docker).
