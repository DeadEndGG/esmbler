# Esmbler.Hosting

Composition root shared by the API, MCP, and worker hosts: service registration, JWT authentication, configuration binding, and the demo tenant seed (`DemoTenants.cs`, which names Tickets IDs only through `TicketsIds`: Acme on Tickets 1.0.0, Globex on the newest release with Jamie as approver). `ServiceRegistration` registers the kernel services (including `WorkspaceCreationPolicy` and `WorkspaceService`), event consumers (including `ApprovalConsumer`) and job handlers (`upgrade.run`, `workflow.migrate`, `approval.expire`, `sla.check`, `notify.resolve`, `notify.deliver`) and the notification service (`SubscriptionRouter`, `NotificationService`, the channel adapters `SmtpEmailChannel` and `HttpSmsChannel` as `INotificationChannel`, `EnvironmentSecretStore` as `ISecretStore`, and the `notifications.sms` `HttpClient` with redirects off), alerts (`AlertRouter` as an event consumer, the `alert.*` job handlers, `AlertService`; ADR 0022) audit (`AuditService`, `AuditMaintenance`; the worker host adds `AuditMaintenanceService` in `apps/Esmbler.Worker/Program.cs`) and email intake (`MailIntakeService`, `MailProcessJobHandler` for `mail.process`, `ImapPoller`; the worker host adds `ImapPollingService`; ADR 0023), the AI catalog (`AiCatalogFactory.From(configuration)` as a singleton `AiCatalog`, and `AiSettingsService`; ADR 0024) and, for every host, `McpConnectionStatus` (whether an external client's connection is still active; ADR 0025); `AddEsmblerOAuthServer()` registers the OAuth authorization server (`HttpClientMetadataSource` as `IClientMetadataSource`, `OAuthService`) and is called only by the API host; a new consumer, job kind or channel adapter is registered here (modules cannot contribute channels).

- Settings: `PlatformOptions` binds the `Esmbler` section (environment `Esmbler__*`); for example `MetricRequestsPerMinute` (default 120) sets the per-person `figures` rate limit the API applies to `/api/dashboards`, `/api/metrics/{id}`, `/api/records/{entity}/groups` (ADR 0019) and `/api/starters/{id}/personas` (ADR 0020); `AllowWorkspaceCreation` (default false: self-service creation is an operator decision) and `MaxWorkspacesPerPerson` (default 5) govern self-service workspace creation (ADR 0020); Compose sets them to true and 100 for local development and acceptance runs. `POST /api/workspaces` has its own fixed per-person rate limit (`LoginThrottle.WorkspacePolicy`, 3 a minute, in the API), audit export and Verify now share `LoginThrottle.ExportPolicy` (`exports`, 2 a minute per person, ADR 0022), and the CSV exports `/api/records/{entity}/export` and `/api/metrics/{id}/export` have `LoginThrottle.RecordExportPolicy` (`record-exports`, 10 a minute per person, ADR 0019); the inbound mail webhook has `LoginThrottle.InboundMailPolicy` (`inbound-mail`, 300 a minute per remote address, ADR 0023), and `/oauth/authorize`, `/oauth/token` and `/oauth/revoke` have `LoginThrottle.OAuthPolicy` (`oauth`, 1,200 a minute per address, rejected with the RFC 6749 `temporarily_unavailable` body, ADR 0025). `Notifications` (ADR 0021) holds `AllowedEmailHosts` (default empty: email can only be captured; `Esmbler__Notifications__AllowedEmailHosts__0=smtp.example.com`), `AllowedSmsHosts` (default `api.twilio.com`), `AllowedImapHosts` (default empty: webhook mailboxes only; `Esmbler__Notifications__AllowedImapHosts__0=imap.example.com`, ADR 0023) and `MaxRecipientsPerEvent` (default 200); `ServiceRegistration` maps them to `NotificationOptions` together with `Esmbler:WebUrl` (links in messages, default `http://localhost:8080`). Compose sets none of them. Channel credentials are `ESMBLER_SECRET__<WORKSPACE_SLUG>__<ENVIRONMENT_KEY>__<NAME>` environment variables per workspace environment (upper-cased, hyphens as underscores, for example `ESMBLER_SECRET__ACME__PROD__SMTP_PASSWORD`; IMAP mailboxes use the names in their `usernameRef` and `passwordRef` settings, such as `IMAP_USERNAME` and `IMAP_PASSWORD`; there is no default), set on the API and worker hosts, never `Esmbler__*` settings.
- AI catalog (ADR 0024): `AiCatalogFactory` reads `Esmbler:Assistant`: the named credentials `anthropic-default` (`AnthropicApiKey` or `ANTHROPIC_API_KEY`), `openai-default` (`OpenAIApiKey` or `OPENAI_API_KEY`), `azure-openai-default` (`AZURE_OPENAI_API_KEY` with an HTTPS `AZURE_OPENAI_ENDPOINT`) and `Credentials__<name>__Provider|ApiKey|ApiKeyVariable|Endpoint`; the catalog (`Defaults`: `claude-opus-5-5` evaluated, `claude-sonnet-5-5`, `gpt-6.1-sol` and `gpt-6-astra` not; or `Catalog__N__Id|Label|Provider|Model|Credential|Effort|InputPerMillion|OutputPerMillion|Evaluated|FallbackModel|AllowedTenants__M`), `EvaluatedModels__N`, `DefaultModel` (or the legacy `Model`) and `MaxDailyBudgetUsd` (default 100). Keys come only from configuration or environment variables.
- OAuth (ADR 0025): `Auth/OAuthService.cs` is the authorization server (authorize, consent, token, revoke, connections), registered only by the API host through `AddEsmblerOAuthServer()`; the MCP host uses only the read-only `Auth/McpConnectionStatus.cs` (checked on every tool call; it also stamps `last_used_at` at most once a minute) and `AgentScopes.ExternalGrantable` (in `Esmbler.Kernel`) for `scopes_supported`. `OAuthService` is `Enabled` only when `Mcp.PublicUrl` is set and `Auth.Issuer` is an absolute `https` URL. `Auth/ClientMetadataSource.cs` (`HttpClientMetadataSource`) accepts only HTTPS client IDs on `Mcp.AllowedClientHosts` (exact host or subdomain), connects only when every resolved address is public (`IsPublic`: no private, loopback, link-local, CGNAT, NAT64, 6to4 or `198.18.0.0/15`), with no proxy and no redirects, 5 s and 64 KB, `application/json` or `application/client-metadata+json` only, cached an hour. `PlatformOptions.Mcp` holds `PublicUrl` (the canonical MCP resource URI; set it identically on the API and MCP hosts) and `AllowedClientHosts` (default `chatgpt.com`, `claude.ai`). `TokenService.McpAudience` is `PublicUrl` when set, else `esmbler-mcp`; `IssueAgent` adds `client_id` and `cid` (the connection) for external clients, and `Sign`/`Verify` make the short-lived signed pending requests (audience `esmbler-oauth-request`). `AuthRegistration` validates MCP tokens against `McpAudience`.
- Invariants: secrets only from environment/configuration; API tokens use audience `esmbler-api`, MCP tokens `esmbler-mcp` or the canonical `Esmbler:Mcp:PublicUrl` when the MCP server is public (no passthrough).
