# Known issues

Failures that could not be fixed after a reasonable effort (execution brief, section 1). Each is isolated, has reproduction steps, and is revisited before its gate closes. Status values: `open`, `workaround`, `fixed`.

| ID | Issue | Repro | Impact | Workaround | Status |
|---|---|---|---|---|---|
| KI-001 | A builder whose rights are revoked keeps receiving draft-change notices (IDs and versions only) until the live connection reconnects | Remove a builder's role while their browser watches a draft | Low: the notices carry no data, and reloading the draft is refused under the new rights | Reconnect evicts the subscription; re-check on each notice planned for Gate 2 | open |
| KI-002 | The per-tenant daily AI spend budget from ADR 0013 is not enforced; only per-turn bounds apply | Send many assistant messages | Cost exposure when a model key is configured | Per-person message rate limit (30/min) and per-turn tool, request and time limits | open (Gate 2) |
| KI-003 | Schema-change classification (REQ-MIG-001) is partial: upgrade reports list base changes, overlay outcomes and declarative migrations, but changes are not labeled expand/backfill/contract | Preview the 1.1.0 upgrade | Builders see what changes, not its migration phase | The report's migrations section shows backfills and conversions | open (Gate 2) |
| KI-004 | The live page highlights elements from chat steps, but selecting an element does not highlight its step in the chat, and removed elements disappear without a fade | Open the builder, hover a step, then click an element | Minor: the chat-to-page link works one way | Hover steps to see their elements | open (Gate 2) |
| KI-005 | Design lint (stylelint rules for tokens) is not in CI; accessibility scans (axe, light and dark) are. Tailwind utilities expose only token names (ADR 0014), but component style blocks and arbitrary utility values are unchecked | — | Raw values could slip into component styles | Review rule in `.claude/rules/renderer-ui.md` | open (Gate 2) |
| KI-006 | In Docker Compose the API port (5080) is published for local tools while the API trusts `X-Forwarded-For` from the web proxy, so a local caller could spoof its address for rate limiting | Call `http://localhost:5080/api/auth/login` with a forged header | Local development only | Do not publish the API port, or set `Esmbler__Auth__TrustForwardedHeaders=false`, in shared environments | open |
| KI-007 | The Claude planner has not been scored on the evaluation suite | No API key in the build environment | Real-model completion rate unknown; the built-in planner passes 43 of 43 | Provide `ANTHROPIC_API_KEY` ([human action](human-actions.md)) and run `dotnet test tests/Esmbler.IntegrationTests --filter Claude_planner` | open |
| KI-008 | Publish requests do not expire after 24 hours (ASM-027), and idempotency keys are not purged | Leave a publish request pending for a day | Low: approval is still bound to the artifact hash and expected revision, so a stale request cannot publish something else | Publish or discard the draft; keys are small | open (Gate 2, durable jobs) |
| KI-009 | Graph consistency tooling is incomplete: failed grant writes are not retried in the background, nothing schedules `RebuildGraphAsync`, the SQL permission predicate has no conformance test against `CanRead`, and integration tests use the in-memory graph rather than a real OpenFGA store | Fail an OpenFGA write after a group change | A grant can be missing until repaired (fail closed: access is denied, never widened) | Re-run the change, or call `RebuildGraphAsync` from an operator script | open (Gate 2) |
| KI-010 | No per-tenant API rate limit; only sign-in, assistant and MCP limits exist | Script many API calls from one tenant | A noisy tenant can consume shared API capacity | Per-user assistant and MCP limits; reverse-proxy limits in deployment | open (Gate 2, G2-M13) |
| KI-011 | The sign-in page always showed the demo account hint, even when demo data was not seeded | Open `/login` on any deployment | Low | Fixed: `GET /api/auth/sign-in-options` returns the demo account only when `Esmbler:SeedDemoData` is on (`Api.ApiTests.Sign_in_page_shows_no_demo_account_unless_demo_data_is_seeded`) | closed |
| KI-012 | Tickets 1.1.0 cannot be provisioned into a new tenant: one sample P1 ticket lacks the impact that 1.1.0 requires. Shipped releases are immutable | Provision a tenant on core.tickets 1.1.0 | None for existing tenants (they reach 1.1.0 by upgrade); the seeded Globex tenant starts on the newest release (1.2.0), whose sample data is fixed | Provision on 1.0.0 or 1.2.0 | open (fixed forward in 1.2.0) |
| KI-013 | Reloading the page while a token refresh is still in flight can present an already-rotated refresh token; reuse detection then ends the session and the person must sign in again | Reload a page several times per second | Low: only very fast repeated reloads; normal navigation is unaffected | Wait for the page to finish loading before reloading; a short reuse grace window is planned with G2-M11 identity work | open (Gate 2) |
| KI-014 | Request and task pages do not update live; new fulfillment tasks appear after a reload | Start fulfillment and watch the Fulfillment tasks tab | Minor: tasks appear within a second but need a reload | Reload the request | open (Gate 2, live record updates) |
| KI-015 | The draft review computes workflow impact (running instances per state) with a full count over the entity on every draft refresh while a draft changes a workflow; counts are not permission-filtered (builders see totals, never records) | Change a workflow in a draft of a large tenant and watch draft refreshes | Cost grows with tenant size; no data exposure beyond counts | Counts are one indexed `GROUP BY` per changed workflow; cache per draft version or compute only for the publish review | open |
| KI-016 | Requests have no way back from `fulfilled` to redo a skipped task, and the shipped 1.2.0 workflow rejects only from `submitted`, so agent rejection never has tasks to cancel; approval-driven rejection (`decline`) exists since 1.3.0 | Skip a task, then try to reopen the request | A skipped task needs a new request | Raise a new request for the skipped work | open |
| KI-017 | The built-in scripted planner (`packages/Esmbler.Assistant`) defaults to Tickets IDs (`core.tickets.ticket`, `core.tickets.record`) and narrates Tickets views by ID; the architecture test that blocks module IDs covers kernel, platform and MCP code, not the assistant | Ask the built-in planner to change a non-Tickets entity without naming it | The scripted planner assumes Tickets when the request is ambiguous | Name the entity; the Claude planner discovers entities through `describe_entity` | open |
| KI-018 | The web client names Tickets IDs in three places: the default route after sign-in (`app.routes.ts`), the ticket navigation icon (`shell.ts`) and the `G T` shortcut (`command-palette.ts`); the architecture test that blocks module IDs covers .NET code only | Install a workspace without Tickets and sign in | The default page and one shortcut assume Tickets | Take the default route and shortcuts from the bootstrap navigation | open |
| KI-019 | The approvals inbox and panel run several queries per step (eligibility with fresh facts, one transaction per inbox item), and nothing limits how many people can delegate to one person | Give one approver hundreds of pending steps | Slower inbox for heavy approvers; no data exposure | Inbox lists at most 100 steps per person; batch the queries in G2-M13 (observability and governors) | open |
| KI-020 | Dead letters (jobs, events, consumers) store the raw exception message, which can include record values, and show it to people with `audit.read` on the Operations page | Make a consumer fail on a value | Low: only administrators and auditors see it, within their workspace | Treat the Operations page as administrative; store a code and a sanitized message (G2-M13 observability) | open |
| KI-021 | The Playwright approval journey (`requests.spec.ts`) failed once with "element not found" on the first run against a freshly built stack, and passed on the next two full runs; the trace was overwritten before it could be read | Rebuild the Compose stack with a fresh volume and run the suite once | Possible cold-start timing in an acceptance test; no product defect identified | Re-run; copy `tests/e2e/test-results` before re-running (traces are kept on failure) and investigate before Gate 2 closes | open |
| KI-022 | `SetFieldAccess.AffectsPermissions` is serialized into stored `permission.field_access` overlay ops and the generated overlay schema (the override lacks `[JsonIgnore]`, unlike the others) | Apply a field-access change and read `kernel.draft_commands.op` | None functionally: the value is computed and ignored on read; it adds a stray property to stored ops and the schema | Add `[JsonIgnore]` once a check confirms stored overlays and artifact hashes do not depend on it (changing it alters serialized ops) | open |
