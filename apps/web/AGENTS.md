# apps/web

The Angular 22 web client: shell, list and record pages, the registry-driven renderer, the AI builder panel and admin pages. Talks only to `apps/Esmbler.Api` (`/api`, `/hubs/live`) through the nginx proxy in Compose or `proxy.conf.json` in `ng serve`.

- Styling: Tailwind CSS v4 mapped onto the design tokens ([ADR 0014](../../docs/adr/0014-tailwind-css-for-the-web-ui.md)). Raw colors live only in `src/styles/tokens.css`; `src/styles.css` holds the Tailwind theme and shared primitives (`.btn`, `.input`, `.badge`, `.callout`, `.table-card`). Rules: `.claude/rules/renderer-ui.md`.
- Approvals (ADR 0016): `/approvals` (`src/app/pages/approvals.page.ts`: inbox, decided-by-you tab, out-of-office delegation) is shown only when the bootstrap's `approvals` flag is set, with a pending-count badge (`Session.pendingApprovals`, `/api/approvals/count`) and a command palette entry; the `activity.approvals` element (`src/app/renderer/approvals.ts`) shows stages and decisions on the record page and offers Approve/Reject only where the server says `canDecide`. The server is authoritative for every decision.
- SLAs (ADR 0018): the `activity.sla` element (`src/app/renderer/sla.ts`) shows a record's timers from `GET /api/records/{entity}/{id}/sla`; it never computes deadlines itself. The builder's review lists running SLA clocks (`slaImpact`).
- Metrics and dashboards (ADR 0019): `/dashboards/:view` (`src/app/pages/dashboard.page.ts`) renders a dashboard view with figures from `GET /api/dashboards/{view}/data` (sent with the viewer's time zone, refreshed every 60 s while visible); home (`app.routes.ts`) opens the first dashboard in the bootstrap's `dashboards`. `src/app/renderer/metrics.ts` renders `display.kpi_tile`, `display.bar_chart` (each bar a keyboard-reachable link, with a table toggle) and `display.metric_table`. The client never computes figures or filters: every figure links to the explorer with the server's `DrillQuery` (`src/app/core/drill.ts`), and the server re-applies permissions.
- Explorer state (REQ-WS-003): the list page keeps its state in the URL (`view`, `filter[]`, `sla[]`, `label` for the drill chip, `q`, `sort`, `dir`, `offset`, `group`, `f.<field>`); keep new list state there so drills and shared links work. `src/app/core/explorer-state.ts` remembers the last list URL and scroll per entity for the session, and the record page returns to it. Group headers come from `GET /api/records/{entity}/groups`; column choices live in `localStorage` under `esm.columns.<tenant>.<env>.<user>.<view>` (workspace, environment, person and view).
- The builder panel shows steps that share a `batch` as one change: "Undo change" on its first step undoes the batch (`wholeChange`), and "Undo" on any other step undoes only that step (ASM-065).
- Workspace creation (ADR 0020): `/workspaces/new` (`src/app/pages/create-workspace.page.ts`) has the steps describe (name, description, starter; the keyword suggestion is advisory), questions (only those without defaults) and review (surfaces from `GET /api/starters`), then `POST /api/workspaces`, an explicit switch into the new workspace and home. The server decides what is created; the page only collects answers. When `GET /api/starters` reports `enabled: false` (the platform default, ADR 0020) the page only says that creation is turned off. The workspaces page links to it.
- Empty states (REQ-WS-006): when dashboard data has `empty`, the dashboard page shows the "No tickets yet" banner with next steps; preview figures (`preview`) render with a "Preview" badge and never as links (buckets have no `drill`). The list page's empty state offers to create the first record (or the catalog for requests). Never show preview values as real ones.
- Create form (`src/app/pages/create.page.ts`): checks and sends only the fields on the form, skipping fields with a default or `defaultExpression`; the server applies defaults and rules, and errors on fields the form does not show appear as a toast. Fields that are required right now (by the field or a rule, for example impact on a P1 ticket), visible and editable but not placed by the layout appear in an "Also needed" card (`extra`) and count as on the form (ASM-082).
- Notifications (ADR 0021): `/notifications` (`src/app/pages/notifications.page.ts`: the inbox with read state and record links, and "What I receive" to mute routes or channels; mandatory routes show "Required" and cannot be muted, and the server refuses it anyway); `/admin/notifications` (`src/app/admin/notifications.page.ts`: channel instances with mode, settings and secret names only, never values, capture proposed for new ones; deliveries with replay; route preview), linked in the sidebar only when `Session.canManageNotifications` (`notifications.manage` or `permissions.admin`). The sidebar's Notifications link shows `Session.unreadNotifications` from `/api/me/notifications/unread-count`, refreshed when the bootstrap loads and every 60 s while the page is visible (`shell.ts`; no push yet).
- Alerts and audit (ADR 0022): `/alerts` (`src/app/pages/alerts.page.ts`: tabs Active, Silenced, Resolved and Maintenance windows; "Only mine"; Acknowledge, Assign to me, Resolve with a note and the timeline when the server says `canRespond`; the window form only for `alerts.manage` or `permissions.admin`), linked in the sidebar and the command palette only when the bootstrap's `alerts` flag is set; the sidebar badge shows `Session.openAlerts` from `/api/alerts/count` (open alerts that are the person's), refreshed with the inbox badge every 60 s while visible (no push yet). `/admin/audit` (`src/app/admin/audit.page.ts`: search with expandable details, CSV and JSON Lines export, the tamper-evidence card with Verify now and the broken banner, retention and legal holds), linked when `Session.canReadAudit` (`audit.read` or `permissions.admin`). Buttons follow the person's actions, but the server decides every right; never show details the API redacted as if they were values.
- Icons only through `esm-icon` (`src/app/ui/icon.ts`, Lucide).
- The production build must not need inline scripts (nginx CSP `script-src 'self'`); keep `inlineCritical` off.
- Hidden field values never reach the client; components render only what the API sends.
- The TypeScript expression evaluator (`src/app/core/expressions`) must pass `packages/Esmbler.Expressions/conformance/cases.json`.
- Tests: `npx ng build && npx ng test --watch=false`; acceptance and axe (light and dark) in `tests/e2e` against the Compose stack.
